# Run 20 - Product polish and secondary UX

contract: Mindris must improve secondary product ergonomics without moving business logic into the frontend.

invariant: The frontend remains a client-only surface. Help content, theme choice, and Markdown exports may be surfaced in the browser, but durable product logic and export generation remain backend-owned.

contract: This run must deliver:
- an internal Mindris guide integrated into the AppShell
- a visible and coherent dark/light theme toggle in the AppShell
- a richer Markdown workspace with DOCX export

decision: The internal guide is embedded as contextual product help, not a separate marketing or documentation site.

decision: Markdown DOCX export is generated by the Python backend using the existing DOCX document builder primitives, not by the frontend and not by a new dependency stack.

failure: Theme support must not break existing workspace affordances or make key surfaces unreadable.

test: Backend tests must validate Markdown DOCX package generation.

test: Frontend validation must keep lint and typecheck green after theme and help-shell integration.
